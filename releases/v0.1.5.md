A fix for a freeze. Like v0.1.4 it contains no game data: you need your own ROM of the USA release (a big-endian `.z64` of 32 MiB, SHA-1 `50558356b059ad3fbaf5fe95380512b9dceaaf52`).

> **Made with AI.** Almost all of the code was written by AI agents (Claude), directed and play-tested by a person.

**Windows:** unzip `Rayman2Recompiled-v0.1.5-windows-x64.zip` and run `Rayman2Recompiled.exe` from that folder (it needs a recent Visual C++ 2015-2022 redistributable, x64). **Linux (x86-64):** extract `Rayman2Recompiled-v0.1.5-linux-x64.tar.gz` and run `Rayman2Recompiled` in that folder (glibc 2.35 or newer, a Vulkan driver, GTK 3 and FreeType; it brings its own SDL2).

**Fixed:** the game no longer risks freezing for good when its sound has been held up for a while. If drawing a frame takes several seconds (on a slow or software graphics driver, such as Mesa's lavapipe on Linux), the music's player could run out of room for the notes the game kept sending meanwhile, lose the event that keeps it running, and stop the game on that frame. Now it drops those late notes instead and the game goes on. Donald Duck: Goin' Quackers, built on the same engine, froze this way; Rayman 2 has not been seen to, but nothing stopped it.
